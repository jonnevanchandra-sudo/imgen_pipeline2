## Purpose

All behavior from v1.0 applies.

Version 1.1 adds `ProductSpec` inside `MandatoryRequirements` to support campaigns where a specific product model must appear in generated imagery. This captures both the product identifier and its key visual descriptors — both are required for accurate downstream image generation.

**Why visual descriptors and not just the model name:** Image generators may not have reliable training data for a specific product model. The model name alone produces generic results. The `key_visual_identifiers` are the actual visual instruction — the name is the label that anchors it.

## ProductSpec Rules

**Include ProductSpec when:**
- The campaign brief names a specific product model (e.g. "feature the Pegasus 41")
- A specific product colorway is mandated
- The product's design is distinctive enough that a generic version would be incorrect

**Omit ProductSpec when:**
- No specific product model is required — generic Nike running shoes are acceptable
- The campaign is brand-level, not product-level

**Multiple products:**
ProductSpec is an array. If the campaign features multiple named products, add one entry per product.

**Downstream flow:**
ProductSpec entries flow to Scene Assembly (Stage 5) as named entities with Near Exact preservation priority. Scene Assembly must generate a PreservationContract per product that includes the model name AND visual identifiers. Both must reach the Prompt Compiler's `brand` key in HIGH.

## Success Criteria

All v1.0 success criteria apply, plus:

✓ ProductSpec populated if campaign names a specific product model

✓ Each ProductSpec entry includes model name, visual identifiers, and visibility requirement

✓ Colorway included only if mandated — not inferred or assumed

✓ Ready for Strategy Layer
