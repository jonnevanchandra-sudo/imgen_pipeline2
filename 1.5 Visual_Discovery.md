# Visual Discovery Framework
Version: 1.0
Stage: 1.5 — Visual Reference Curation
Position: After Stage 1 (CampaignContract complete), before Stage 2 (pipeline continues immediately)

---

## Purpose

Stage 1.5 captures the client's aesthetic preferences before the pipeline makes any visual decisions.

Art Direction (Stage 4) derives all visual direction from brand and strategic context alone. Visual Discovery gives the client a mechanism to weigh in on aesthetic direction — without waiting for the full pipeline to complete.

**This stage does not make visual decisions.** It generates curated reference options for the client to react to. The client's picks are codified later at Stage 5.5 (Client Preference Ingestion), then fed into Scene Assembly as optional input.

**Pipeline continues immediately.** The app dispatches the VisualDiscoveryPackage to the client, and Stage 2 (Strategy) begins without waiting. The client's response is asynchronous.

---

## Decision Architecture

| Layer | Decision Type |
|---|---|
| Campaign Brief | Campaign Definition |
| **Visual Discovery** | **Reference Curation (client-facing)** |
| Strategy | Meaning Selection |
| Narrative | Emotional Interpretation |
| Art Direction | Visual Interpretation |
| Scene Assembly | Scene Construction |

**Boundary rule:** Visual Discovery generates options for client reaction only. It must NOT:
- Define VisualIntent, VisualConcept, or any Art Direction output
- Make aesthetic selections on behalf of the client
- Prescribe visual execution

## Inputs

### From Campaign Brief (Stage 1)
- `CampaignContract.CampaignTheme.theme_token`
- `CampaignContract.AudienceContext.primary_audience`
- `CampaignContract.ChannelContext.primary_channel`
- `CampaignContract.MessageHierarchy.primary_message`

### From Brand Intelligence (Stage 0, if available)
- `BrandContract.RenderingStyle` — used to bias archetypes toward brand-compatible directions
- `BrandContract.SacredBrandAssets` — used as exclusion guardrail (do not generate archetypes that conflict with locked brand identity)

---

## What to Generate

Produce **5–8 visual reference archetypes** — distinct aesthetic directions that could plausibly serve this campaign.

Each archetype must be:
- **Genuinely distinct** — different enough that a client's choice between them carries real aesthetic information
- **Campaign-compatible** — defensible against the campaign brief, audience, and channel
- **Client-legible** — described in plain language a non-creative client can react to

### Per-Archetype Fields

| Field | Description |
|---|---|
| `id` | Short unique identifier: `ref_A`, `ref_B`, etc. |
| `name` | Short evocative name (2–4 words). e.g. "Warm Documentary", "Minimal High Key" |
| `visual_description` | 2–3 sentences describing what images in this direction look like: lighting, subject scale, color register, mood, compositional feel |
| `emotional_tone` | 1 sentence: the feeling a viewer gets from this visual direction |
| `genre_reference` | Named photography/advertising genre or cultural reference point that grounds the archetype. e.g. "gritty documentary sports photography", "Scandinavian lifestyle advertising", "Japanese street editorial" |
| `google_image_query` | A specific search query designed to return useful aesthetic reference images. **Must include explicit photography style/genre terms** — Google Images is broad, so the query must do the filtering work. Bad: `"warm running night"`. Good: `"warm amber city night running lifestyle editorial photography"` |
| `campaign_alignment_note` | 1 sentence explaining why this direction is compatible with this specific campaign |

### Google Images Query Rules

Google Images does not curate by aesthetic the way Pinterest does. Every query must contain:
1. Subject/activity terms (what is in the image)
2. Photography style/genre terms (what kind of image it is)
3. Mood/lighting terms (the visual register)

Example for a nighttime running campaign:
- `"warm city night running lifestyle editorial photography"`
- `"documentary street running photography golden hour urban"`
- `"fashion editorial running urban night warm tones"`

**App implementation note:** Construct clickable URL as:
`https://www.google.com/search?q={url_encoded_query}&tbm=isch`
No API key required for client-facing links. For programmatic image retrieval, use the Google Custom Search JSON API.

## Output

```json
{
  "VisualDiscoveryPackage": {
    "metadata": {
      "brand": "string",
      "campaign": "string",
      "framework": "Visual Discovery v1.0",
      "stage": "1.5",
      "campaign_theme": "string",
      "channel": "string"
    },
    "archetypes": [
      {
        "id": "ref_A",
        "name": "string",
        "visual_description": "string",
        "emotional_tone": "string",
        "genre_reference": "string",
        "google_image_query": "string",
        "campaign_alignment_note": "string"
      }
    ],
    "client_prompt": "string"
  }
}
```

### `client_prompt` guidance

Write a plain-language question to show the client alongside the archetypes. It should:
- Ask which directions feel right and why
- Ask which directions feel wrong and why
- Invite the client to share any reference images of their own

Example:
> "Here are several visual directions we could take this campaign. Which of these feels right for you — and more importantly, what specifically draws you to it? If any feel off, let us know what doesn't work. You can also share any images of your own that capture the feeling you're after."

---

## Downstream Flow

The VisualDiscoveryPackage is dispatched to the client by the app while the pipeline continues.

When the client responds, their picks are fed into **Stage 5.5 (Client Preference Ingestion)**, which codifies them into a `ClientPreferenceContract`. That contract is then passed as optional input to Stage 5.2.5 (Scene Assembly).

If the client does not respond before Stage 5.2.5 runs, Stage 5.5 is skipped and Scene Assembly runs without client preferences — exactly as if Stage 1.5 had not run.

---

## Success Criteria

✓ 5–8 archetypes generated, each genuinely distinct from the others

✓ Every `google_image_query` includes explicit photography style/genre terms (not just mood words)

✓ Every archetype is defensible against the campaign brief

✓ No archetype conflicts with `BrandContract.SacredBrandAssets` (if BrandContract was provided)

✓ `client_prompt` is written in plain language a non-creative client can act on

✓ Stage 2 (Strategy) can begin immediately — this stage's output does not block the pipeline
